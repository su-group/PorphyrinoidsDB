# 特征处理与超参搜索空间分析（针对「9000 多特征是否在筛选」）

- 分析对象：`E:\Project-ZhangChengwei\PorScaDB-ML-compute-20261014\PorScaDB-ML`
- 触发问题：混合特征 9972 列是否被筛选？为什么混合组又慢又出现效果分化？
- 触发消息：用户提问「按理说不是应该将9000多的特征进行特征筛选提取吗？难道现在是全量数据吗」
- 结论一句话：**筛选确实在跑（折内、无泄漏），指纹也确实有真实贡献；真正的病根是核方法的超参搜索空间把最优参数区挡在外面。**

---

## 1. 筛选确实在跑，而且是折内筛选（无泄漏）

`core/train_optimizer.py` 的 `fit_preprocessing` 在**每个折内**只用训练折的数据做：

1. 去掉含 `Spin` / `Y_number` 的列、全 NaN 列；
2. 中位数填充 → 方差筛选：`var > 0.01` 作候选（候选不足 50 时退化为 `var > 1e-10`）；
3. 按与目标的 |相关系数| 降序，贪心去相关：与已保留列 |corr| > 0.95 则丢弃；
4. 保留数不足 50 时取相关性前 50。

实测各组的折内保留列数：

| 配置 | 原始列 | 折内保留（fold0） | 保留列族构成 |
|---|---|---|---|
| R-M（纯 Mordred） | 1613 | **523–525** | mordred 全占 |
| R-MF（Mordred+全指纹） | 9972 | **3986** | AtomPair 1042 / RDKitFP 2039 / Morgan 234 / TopoTorsion 117 / MACCS 44 / **mordred 仅 510** |

要点：

- 9972 → 约 3986，**只砍掉约 60%**，远不是"提取"；
- 保留列里 **87% 是指纹位**，化学意义最强的 Mordred 描述符只留下 510 个；
- 原因：指纹位之间几乎正交、且贪心去相关按目标相关性排序，正交的稀疏位不容易互相"淘汰"，于是把 Mordred 挤了出去。

所以用户的直觉方向是对的——**筛选存在，但对指纹那一块筛得太轻**。

## 2. 指纹的真实作用：随机划分里明显有用，骨架外推里没用

用项目自己的折内筛选规则 + 折内 `StandardScaler`，在同一批折上做受控对比。**指标是五折合并后的 CV MSE / CV R²**（骨架划分各折 `y_valid` 方差差很多，sd 0.31–1.62 eV，逐折 MSE 取平均会主要反映这种方差差异而不是预测力）。

### 2.1 随机划分（`splits.json` 的 random，折位置取自 `experiments\20261016_R-M`）

锚点：仅 Mordred 的 Lasso 合并 CV MSE = 0.270594（管线 100-trial 上报 0.270567，吻合）。

| 特征配置 | 原始列 | 折内保留 | Lasso (R-M best) | RandomForest (R-M best) | SVR (修正空间最优) |
|---|---|---|---|---|---|
| 仅 Mordred | 1613 | 525 | 0.2706 / R²+0.7516 | 0.1556 / +0.8572 | 0.1980 / +0.8182 |
| Mordred+Morgan | 3661 | 774 | 0.1396 / +0.8719 | 0.1112 / +0.8980 | 0.1586 / +0.8544 |
| Mordred+MACCS | 1780 | 579 | 0.2418 / +0.7780 | 0.1404 / +0.8711 | **0.1564 / +0.8564** |
| Mordred+RDKitFP | 3661 | 2566 | 0.1381 / +0.8732 | 0.1119 / +0.8973 | **0.1260 / +0.8844** |
| Mordred+AtomPair+TopoTorsion | 5709 | 1677 | **0.1189 / +0.8909** | 0.1112 / +0.8980 | 0.1680 / +0.8458 |
| 全部指纹 | 9972 | 3977 | 0.1282 / +0.8823 | **0.1049 / +0.9037** | 0.1478 / +0.8643 |

结论：**随机划分下指纹是真增益**（Lasso 0.2706→0.1282 约 2.1×，RandomForest 0.1556→0.1049，SVR 0.1980→0.1260）；单族里 **RDKitFP 在 SVR 上最好、AtomPair+TopoTorsion 在 Lasso 上最好**，全量并不是处处最优。

### 2.2 骨架划分（折位置取自 `experiments\20261014_S-M`）

同一套代码、同一套指标，模型固定用 S-M 自己调出的超参（Lasso alpha=0.0070375；RandomForest n_estimators=32/max_depth=8）。

| 特征配置 | 原始列 | 折内保留 | Lasso (S-M best) | RandomForest (S-M best) | SVR (固定 C/gamma) |
|---|---|---|---|---|---|
| **仅 Mordred** | 1613 | 524 | **0.6101 / R²+0.4534** | **2.6163 / −1.3439** | **1.5808 / −0.4162** |
| Mordred+Morgan | 3661 | 717 | 1.2760 / −0.1432 | 3.0118 / −1.6983 | 1.3336 / −0.1947 |
| Mordred+MACCS | 1780 | 569 | 0.8453 / +0.2427 | 2.8714 / −1.5725 | 1.6533 / −0.4812 |
| Mordred+RDKitFP | 3661 | 2525 | 1.2278 / −0.1000 | 2.8745 / −1.5752 | 1.1690 / −0.0473 |
| Mordred+AtomPair+TopoTorsion | 5709 | 1497 | 1.2791 / −0.1460 | 2.8811 / −1.5812 | 1.1793 / −0.0565 |
| 全部指纹 | 9972 | 3687 | 1.4347 / −0.2853 | 3.0289 / −1.7136 | 1.2203 / −0.0933 |

**结论（回答用户的质疑）：骨架外推下指纹没有任何配置能追平纯 Mordred，而且全部变差。** 最好的指纹配置（Lasso+MACCS）合并 CV MSE 0.8453、CV R² +0.2427，仍显著劣于仅 Mordred 的 0.6101 / +0.4534。

（脚本：`.dsh_tmp\fp_random_ablation.py`、`.dsh_tmp\fp_scaffold_ablation.py`；结果：`指纹-随机折内消融.md`、`指纹-骨架折内消融.md`）

> 两处口径说明：① 受控实验里的绝对数值普遍差于管线上报值，因为模型超参是在“纯 Mordred”上选出来的，直接搬到加了指纹的特征集上属于不公平比较——但这只会让指纹显得**更好**，结论方向不受影响；② 骨架划分下超参若在每个特征配置上重调，可能让指纹配置追回一些，但预期收益有限。

## 3. 真正的病根：核方法的超参搜索空间过窄

`config/hyperparameter_optimization.json` 原配置只给核方法留下了很窄的区间：

| 参数 | 原区间 | 150-trial TPE 选到的最优 | 说明 |
|---|---|---|---|
| SVR `C` | [0.1, 100] | **960.8** | 顶到边界，真最优在外面 |
| SVR `gamma` | [0.001, 1] | **3.34e-05** | 比下界低 **30 倍**，根本够不着 |
| SVR `epsilon` | [0.01, 1] | 0.0011 | 平地上，见第 4 节 |
| KernelRidge `alpha` | [0.01, 10] | **99.88** | 上界差 10 倍 |
| KernelRidge `gamma` | [0.001, 1] | 0.0511 | 需要更大带宽 |

在同一批折内矩阵上、同样 150 trial TPE，仅把区间放宽后可获得的提升：

| 运行 | 模型 | 原空间最优 CV MSE | sklearn 默认 | **修正空间最优 CV MSE** | 提升 |
|---|---|---|---|---|---|
| R-MF（3977 列） | SVR | 0.4565 | 0.1577 | **0.0912**（CV R² +0.9109） | **5.00×** |
| R-MF | KernelRidge | 0.6488 | 0.2033 | **0.1110**（CV R² +0.8915） | **5.84×** |
| R-M（525 列） | SVR | 0.2381 | 0.4015 | **0.1971**（CV R² +0.8108） | 1.21× |
| R-M | KernelRidge | 0.3681 | 0.4039 | **0.2658**（CV R² +0.7462） | 1.38× |

（脚本：`.dsh_tmp\fixed_space_test.py`，结果 `.dsh_tmp\fixed-space-R-MF.txt` / `fixed-space-R-M.txt`）

机理：**样本少（1109）× 特征多（3977）时，核方法需要"强正则 + 极窄带宽"**。原空间两个方向都被卡死，Optuna 只能在边界上挑，挑出来的还不如 sklearn 默认值——这正是混合组 SVR 从随机划分的 R² 0.88 掉到 0.57 的原因（并非指纹有害）。

### 已落地的修改

`config/hyperparameter_optimization.json`（只动核方法两段，其余 8 个模型不动）：

| 参数 | 原 | 新 |
|---|---|---|
| SVR `C` | [0.1, 100] | **[0.01, 1000]** |
| SVR `gamma` | [0.001, 1] | **[1e-05, 0.2]** |
| SVR `epsilon` | [0.01, 1] | **[0.001, 1]** |
| KernelRidge `alpha` | [0.01, 10] | **[1e-05, 1000]** |
| KernelRidge `gamma` | [0.001, 1] | **[1e-05, 0.2]** |

备份：`.dsh_tmp\hyperparameter_optimization.corrected.json`。改动经 `run_pipeline.py:256` 记入 `run_metadata.json` 的 `source_sha256`，可追溯。

修改后在真实流水线上复现（`experiments\20261016_R-M`，同一 `splits.json`）：

| 模型 | 修正前 CV MSE | 修正后 CV MSE | Test R²（前 → 后） |
|---|---|---|---|
| **SVR** | 0.2381 | **0.1980** | 0.8849 → **0.8880** |
| **KernelRidge** | 0.2568 | **0.1989** | 0.8610 → **0.8623** |
| Lasso | 0.2706 | 0.2706 | 0.8119（逐位不变） |
| ElasticNet | 0.2655 | 0.2655 | 0.8137（不变） |
| KNeighbors | 0.6008 | 0.6008 | 0.4094（不变） |
| DecisionTree | 0.2195 | 0.2195 | 0.8064（不变） |

**只有核方法变化，其余 8 个模型逐位不变**——这是最干净的对照，证明提升来自搜索空间修复而非随机性。

CV MSE 降 17–23%，但测试 R² 只涨 0.001–0.003：测试集仅 347 样本，单次测试成绩方差大，**选型应以 CV 为准**（本项目本身也只用 CV 选型）。

## 4. `epsilon` 下界不需要再降（已闭环）

把修正空间选出的最优点固定（`C=27.456, gamma=3.343e-05`），只扫 `epsilon`：

| epsilon | CV MSE | | 变量 | CV MSE |
|---|---|---|---|---|
| 1e-3 | 0.09124 | | gamma 3.343e-05（选中） | **0.09124** |
| 3e-4 | 0.09123 | | gamma 1e-5 | 0.11697 |
| 1e-4 | 0.09123 | | gamma 1e-6 | 0.25373 |
| 3e-5 | 0.09123 | | C 27.46（选中） | **0.09124** |
| 1e-5 | 0.09123 | | C 100 | 0.10357 |
| 1e-6 | 0.09123 | | C 300 | 0.13055 |

`epsilon` 从 1e-3 降到 1e-6 完全平台化（只动小数第 5 位），说明它撞下界只是"平地上多走一步"，**不是被卡住**；`gamma` 与 `C` 才是有真实极值谷的参数。另在加宽空间（`gamma≥1e-7, epsilon≥1e-7`）跑了 60-trial TPE，最优 CV MSE = 0.09298，**没超过**修正空间的 0.09124——即修正后的区间已覆盖最优区，可以停止调参。

（脚本：`.dsh_tmp\probe_svr_bounds.py`，日志 `.dsh_tmp\probe-svr-bounds.log`）

## 5. 代价：算力被高维指纹吃掉

| 事项 | 实测 |
|---|---|
| 折内筛选耗时 | 9972 列、单折约 2 秒，5 折一次（折内做一次，trial 之间复用，不是每 trial 重算） |
| GP 单次拟合 | 525 列 **13 秒** → 3977 列 **5.3 分钟**（**24×**，样本数不变、只改特征数） |
| GP 每 trial | 约 **27 分钟**（3977 列 + `n_restarts_optimizer=2`）→ 100 trial 约 **45 小时** |
| GP（我的受控实验，`n_restarts_optimizer=0` + 固定初值） | 3986 列约 **2.5 分钟/折**，CV MSE 0.1027 |

所以混合组的慢**不是卡死**，而是 3977 列进了 GP 的边际似然优化。可选处置：

1. 混合组的 GP 降 `n_restarts_optimizer`（实测 0 + `ConstantKernel*RBF` 初值即可到 CV MSE≈0.10）；
2. 或用固定核参数的 KernelRidge 替代 GP（修正后 CV MSE 0.1110，成本低几个数量级）；
3. 或给指纹族限位数（如每族前 100 个高方差位）——受控实验里 `capped100` 版 XGBoost CV MSE 0.0804 仍优于纯 Mordred 的 0.0970，但弱于全指纹 0.0761。
